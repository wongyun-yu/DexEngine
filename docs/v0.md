# DexEngine v0

v0 is the code release that matches the released v0 data (wuji2 and SharpA). It carries the data-generation behaviour
that produced that data, with the code cleanup of v0.1 applied (package layout, formatter, English, design checks,
output-identical speed-ups, hand/arm/mount by config). The behaviour changes that v0.1 makes are listed in the v0.1
branch, on its page "Changes from v0".

## Reference

v0 reproduces the code that generated the released v0 data:

- Collection, render and placement: the generation code of that data.
- Augmentation cells and extra cells: the cell rules (canonical cell fit, whole-cell shift, place reselect,
  canonical volume exemption, user hold table), the f0-key region-dump reuse and a 1-ulp same-function check of the
  region dump.
- Final merge: the `ORIG_DUP` rule (an original re-render of a clip already in the final skips just that clip).

## Differences from the generation code

- **Head camera:** the training robot's head camera body and the frame-0 repair's robot description carry the robot's
  ZED Mini (Stereolabs mesh, datasheet mass) at the calibrated mount, as in v0.1, instead of a larger stand-in camera
  body of untraced origin. The frame-0 input key of SharpA trees changes once; frame-0 values do not change (the hand
  kinematics and the hand collision description are identical).

## Known limits

- **Not byte-reproducible from v0:** the SharpA judge and RL stages were run with older code, and the wuji2
  collection and render with collection code older than the reference. v0 reproduces that code's
  outputs, not those stored bytes.
- **Merge and top-up selection** are operating rules outside this repository. The public code takes the top-up table
  as an input (SharpA finals: 3,035 top-up episodes; wuji2: none).
- **wuji2 judge scope:** wuji2 judged only the clips that the first-generation Wuji hand had not dropped for
  hand-independent reasons (a provisional carry of that hand's final ledger). That carry and the first-generation hand
  are not part of this release.
- **Language annotations** use the text rules of the version that wrote the released text. The text is produced
  by a language model and is not byte-reproducible.
- **OakInk2 articulated-object clips:** clips whose stage-1 trees were built before articulated objects that barely
  move during the clip (hinge ≤ 2°, slide ≤ 0.5 cm) were merged into one rigid body are not in the v0 SharpA data
  (130 clips); v0.1 regenerates them with the merge.
- **xr repair and the math library:** the xr hand-pair penetration repair is sensitive to a 1-ulp difference in the
  system math library: on a 50-clip sample, 24/50 output arrays can differ across machines and 1/50 repair verdicts
  (REPAIRED/FAILED) flip; tracking-error differences are ≤ 0.13 mm and ≤ 0.007°. v0.1 makes this path
  machine-independent.
