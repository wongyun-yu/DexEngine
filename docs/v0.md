# DexEngine v0

v0 is the code release that matches the released v0 data (wuji2 and SharpA). It carries the data-generation behaviour
that produced that data, with the code cleanup of v0.1 applied (package layout, formatter, English, design checks,
output-identical speed-ups, hand/arm/mount by config). The behaviour changes that v0.1 makes are listed in the v0.1
branch, on its page "Changes from v0".

## Reference

v0 reproduces the code that generated the released v0 data:

- Collection, render and placement: the generation code of that data.
- Augmentation cells and extra cells: the cell rules (canonical cell fit, whole-cell shift, place reselect,
  canonical volume exemption, user hold table), the f0-key region-dump reuse and a 1-ulp same-function check of the
  region dump.
- Final merge: the `ORIG_DUP` rule (an original re-render of a clip already in the final skips just that clip).

## Differences from the generation code

- **Head camera:** the training robot's head camera body and the frame-0 repair's robot description carry the robot's
  ZED Mini (Stereolabs mesh, datasheet mass) at the calibrated mount, as in v0.1, instead of a larger stand-in camera
  body of untraced origin. The frame-0 input key of SharpA trees changes once; frame-0 values do not change (the hand
  kinematics and the hand collision description are identical).
- **One render path:** every robot frame comes from the record render (`scripts/stage4_record.py`) under one look,
  look D. `dexengine.record.looks.look_d.apply` builds the room walls itself (same geometry as before), zeroes the env
  cfg's dome and key light and binds look D's own floor, wall, ceiling and desk materials. The old render look's base
  layer, which look D drew over before the first frame, is gone, so the visible output is meant to be unchanged;
  render_meta's `render_look.applied.canon_lights_prev` records the dome at the env cfg's intensity instead of 1600,
  and cached renders are drawn again once (the record render's cache key covers the new look files).
- **Frame guard:** `dexengine.record.looks.look_guard` makes the record rig's camera read, the episode writer, the
  random looks' reference stills, the pose still and the video encoders of the closed-loop evaluation (E5) die unless
  look D was applied to the current stage in the same process. Render session logs must carry the token line.
- **RL renderers removed:** the per-clip policy and replay videos, the tiled trajectory replay
  (`DEXENGINE_TRAJ_RENDER`), the four-view kinematic replay, `cell_tools render`, `cell_session replay`, the gym
  viewport recorder (`--video`), the RSI still frames and the video after bimanual training (`DO_VIDEO`,
  `--no-video`) are gone. The trainer draws nothing; with `--record_session` it hands its env to the record session's
  function (`dexengine.rl.session_render`) and dies when no session attached one. `RENDER_ONLY` and
  `FROZEN_RENDER_OUT` only write dumps (`DRYRUN=1`). Removed inputs die with a pointer to the record render
  (`dexengine.rl.render_removed`). `rl.render.pose_check` applies look D and passes the frame guard. The training and
  judge launches are unchanged (their launch records are identical).
- **Render-only objects of a root without the axis hand:** the generator of the record's render-only object index
  (`python -m dexengine.record.scene.render_only_build`) takes `--root-hands <hand>[,…]` for a root that does not hold
  the axis hand (for example one with `wuji2` only). The statement is checked against the base layers (a stated hand
  without base trees, a hand with base trees left out, or an unknown hand dies); every clip then takes the base tree of
  the first hand by name that has it. Without the statement such a root dies as before.
- **Render-only object index built by the record:** `scripts/stage4_record.py drive` and `bundle` build a dataset's
  missing render-only object index for the whole dataset before their work (the generation code died with
  "render-only object index missing … run the generator first"). The hands are derived from the base layers: the axis
  hand when it has base trees, otherwise the one hand of the root; any other root dies, and a clip that cannot be
  measured writes nothing and stops the run. An index already present is used as it is.

## Known limits

- **Not byte-reproducible from v0:** the SharpA judge and RL stages were run with older code, and the wuji2
  collection and render with collection code older than the reference. v0 reproduces that code's
  outputs, not those stored bytes.
- **Merge and top-up selection** are operating rules outside this repository. The public code takes the top-up table
  as an input (SharpA finals: 3,035 top-up episodes; wuji2: none).
- **wuji2 judge scope:** wuji2 judged only the clips that the first-generation Wuji hand had not dropped for
  hand-independent reasons (a provisional carry of that hand's final ledger). That carry and the first-generation hand
  are not part of this release.
- **Language annotations** use the text rules of the version that wrote the released text. The text is produced
  by a language model and is not byte-reproducible.
- **OakInk2 articulated-object clips:** clips whose stage-1 trees were built before articulated objects that barely
  move during the clip (hinge ≤ 2°, slide ≤ 0.5 cm) were merged into one rigid body are not in the v0 SharpA data
  (130 clips); v0.1 regenerates them with the merge.
- **xr repair and the math library:** the xr hand-pair penetration repair is sensitive to a 1-ulp difference in the
  system math library: on a 50-clip sample, 24/50 output arrays can differ across machines and 1/50 repair verdicts
  (REPAIRED/FAILED) flip; tracking-error differences are ≤ 0.13 mm and ≤ 0.007°. v0.1 makes this path
  machine-independent.
